# 개념 정리, 숫자, 정확성 주의점, 예상 질문

발표자가 질문에 버틸 수 있도록 정리한 문서. 영상에 나오는 숫자는 코드에서 실제로 계산한 값이다.

## 1. 편미분 (영상 1)

- 함수: z = 0.15x² + 0.25y² + 0.2xy + 0.5, 점 (1.5, 1).
- ∂z/∂x = 0.3x + 0.2y → 0.65, ∂z/∂y = 0.2x + 0.5y → 0.80.
- 편미분은 **식**이고, 현재 값을 **전부** 대입하면 숫자가 된다 (미분한 그 변수 자신의 값 포함).
- Δz ≈ 0.65·Δx + 0.80·Δy. Δx = Δy = 0.1이면 0.145 (실제 0.151). 작게 움직일수록 정확.
- 왜 더해도 되나: 점 근처는 평평한 판(접평면)이라 대각선 이동 = x 이동 + y 이동.

## 2. 기울기와 학습률

- 기울기(gradient) = 편미분을 모은 화살표. **오르막**을 가리킨다.
- 걸음 규칙: Δwᵢ = −η × ∂L/∂wᵢ. η = 학습률 = 모든 방향에 똑같이 곱하는 상수.
- 이 규칙이면 ΔL ≈ −η × (각 기울기의 제곱 합) < 0 → 반드시 내려간다 (단, 걸음이 작을 때).
  - 주의: 이 "제곱"은 일부러 만든 게 아니라 대입하면 저절로 나온다. 손실 함수의 (예측−정답)²과는 다른 제곱이다.
- 왜 경사에 비례해서 걷나: 같은 거리를 걸을 때 가장 많이 내려가는 방향이 기울기의 정반대다. 그리고 바닥에 가까울수록 걸음이 저절로 작아진다.
- 학습률이 너무 크면 근사가 깨져서 출렁이거나 발산한다.

## 3. 공 굴리기 (영상 2)

- 지형: L(w1, w2) = 0.16(w1² + w2²) − 1.3·exp(…) − 0.8·exp(…) + 0.12·sin·cos + 1.5. 골짜기 2개.
- 공 1: (2.5, 1.9)에서 출발, 학습률 0.25, 손실 3.18 → 0.51 (깊은 골짜기).
- 공 2: (−2.4, 2.5)에서 출발, 손실 → 1.20 (얕은 골짜기 = 지역 최솟값).
- 나침반 색 = 각 방향의 변화량 (w₁ 몫 + w₂ 몫). 바늘 길이 = 경사의 세기.
- 실제 LLM에서는 지역 최솟값이 생각보다 큰 문제가 아니라는 연구가 많다. 깊게 들어가지 말 것.

## 4. 손실 (선택 영상)

- LLM 손실 = 크로스 엔트로피 = −log(정답 단어에 준 확률).
- 5.3% → 2.94, 74% → 0.30. 100%면 0.
- 영상의 5개 문장 손실(2.94, 0.41, 1.20, 0.73, 1.85)의 평균 1.43은 예시 값.

## 5. ΔW와 행렬 (영상 3)

- 학습 중 **데이터(텍스트 → 4096차원 벡터)는 상수**, **가중치는 변수**. 미분은 가중치로 한다.
- 4096 = 한 층의 폭(hidden size). 70억 = 모든 행렬 칸의 합.
- Llama-2 7B 계산: 층 하나에 Attention 행렬 4개(4 × 4096 × 4096 ≈ 6,700만) + FFN 3개(3 × 4096 × 11008 ≈ 1억 3,500만) ≈ 2억. × 32층 ≈ 65억, + 임베딩 ≈ 67억 ≈ "약 70억".
- 풀 파인튜닝은 가중치 하나당 기울기 + Adam 기록 2개(평균, 크기)까지 들고 있어야 한다.

## 6. LoRA (영상 4)

- 식: h = Wx + (α/r)·BAx. W는 고정, B(d × r)와 A(r × d)만 학습.
- **표현하는 건 W가 아니라 변화량 ΔW**다. 원본 압축(양자화·프루닝)과 다른 기술.
- 구구단표 = 열 × 행 = rank 1. B × A = rank-1 패턴 r개의 합.
- 영상의 예시 ΔW: 12 × 12, 센 패턴 3개(특이값 약 7.2, 5.7, 1.6, 나머지 약 0.3). r = 1, 2, 3 근사 오차 64%, 18%, 6%.
- 학습 시연: B = 0, A = 랜덤에서 시작, 학습률 0.05, 120걸음에 오차 100% → 6%.
- 크기: d = 4096, r = 8이면 2 × 4096 × 8 = 65,536 = 1,677만의 0.39%.
- B = 0으로 시작하는 이유: 학습 첫 순간 BA = 0이라 원본 모델과 완전히 같게 출발.
- 추론: 학습 후 W' = W + (α/r)BA로 합치면 추가 연산 없음.

## 7. LoRA 논문 수치 (Hu et al., 2021, GPT-3 175B)

- 학습할 숫자 약 1만 배 감소, 학습 중 GPU 메모리 약 3배 감소 (1.2TB → 350GB).
- 체크포인트 350GB → 35MB (r = 4, Wq·Wv에만 적용).
- 학습 처리량 약 25% 향상, 추론 지연 없음.
- Wq, Wv 둘 다 적용하면 r = 1로도 충분했던 경우가 있었다.
- 출처: https://arxiv.org/abs/2106.09685

## 8. r과 α (본편 밖, 질문 대비)

- r: B, A의 두께 = 겹칠 패턴 개수. 키우면 표현력·비용↑, 성능은 금방 포화. 보통 8~32에서 시작.
- α: 패치의 볼륨. (α/r)로 나눠서 r을 바꿔도 세기가 비슷하게 유지. α를 키우면 사실상 학습률을 키우는 효과.
- target modules: 원 논문 기본은 Wq, Wv. 요즘은 Attention 전부 + FFN까지 붙이는 경우가 많다.
- r이 아주 크면 α/r 스케일이 너무 줄인다는 연구(rsLoRA, α/√r 제안)도 있다.

## 9. 예상 질문과 답

| 질문 | 답 |
|---|---|
| 왜 low-rank로 충분한가? | 파인튜닝의 변화는 몇 개 방향에 몰려 있다는 게 LoRA의 가정이고, 실험으로 확인됐다. 참고로 데이터 하나에 대한 한 층의 기울기는 (뒤 신호 열) × (앞 입력 행) = rank 1이다. 배치가 쌓이면 rank가 오르지만 몇 개 방향에 몰리기 쉽다. |
| r은 어떻게 정하나? | 작게(8~32) 시작해서 부족하면 올린다. 데이터가 적으면 큰 r은 과적합 위험. |
| 추론이 느려지나? | 아니다. W + BA로 합쳐 두면 원래 모델과 같은 크기다. |
| 원본 모델이 바뀌나? | 아니다. W는 얼려 두고 B, A만 저장한다. 과제마다 작은 패치만 갈아끼운다. |
| 학습률이 크면? | 근사가 깨져서 출렁이거나 발산한다. |
| 지역 최솟값에 갇히면? | 고차원에서는 크게 문제 되지 않는 경우가 많다. 깊게 들어가지 말고 "출발점에 따라 결과가 달라질 수 있다" 정도로. |
| 기울기는 어떻게 70억 개를 다 구하나? | 역전파가 뒤에서부터 한 번에 계산한다. 원리(연쇄법칙)는 이번 발표 범위 밖. |
