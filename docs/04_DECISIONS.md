# 결정 기록

시간순. "무엇을, 왜"를 남겨서 같은 논의를 반복하지 않게 한다.

## 주제

- 테코톡 주제를 『HOW TO 맥킨지 문제해결의 기술』 → **LoRA 학습**으로 확정.
- 제목: **LoRA로 보는 파인튜닝과 학습의 원리**. "모델의 main 브랜치는 건드리지 마세요" 같은 git 비유는 제목 대신 오프닝 멘트로.

## 구조

- 준비 방식 피드백: "주제 학습 → 정리 → 목차" 순서로 하면 계속 갈아엎게 된다. **흐름(배경 → 문제 → 해결 → 전체 그림 → 세부 → 회수)과 메인 메시지를 먼저 정하고 내용을 채운다.**
- 발표 방식: **영상 보고 → 설명 → 영상 보고 → 설명.**

## 넣기로 한 것

- **편미분을 먼저 설명한다.** 기울기(gradient)를 바로 쓰면 이해가 안 되기 때문. "하나만 남기고 고정 → 단면 → 그 방향의 델타"를 3D로 보여준다.
- **저차원 → 고차원.** 가중치 1개 → 2개 → 70억 개.
- **공이 굴러 내려가는 느낌의 영상** (3Blue1Brown 딥러닝 2장 참고, 그림은 자체 제작).
- 공 영상의 왼쪽은 **좌표 평면 대신 나침반(원)**. 일반 청중에게 좌표 평면은 "이게 뭐지?"가 되기 때문.
- **작은 행렬 두 개로 큰 행렬을 표현하는 원리**를 제대로 설명하는 영상 (구구단표 → 패턴 겹치기 → 근사 → 학습).
- 손실은 LLM이 실제로 쓰는 방식(−log p)으로 보여준다.

## 용어

- 화면 문구에서 "입력"이라는 단어를 가중치 의미로 쓰지 않는다. 텍스트(데이터)와 헷갈리기 때문. → "가중치" 또는 "변수".
- LoRA가 표현하는 것은 **W가 아니라 ΔW**라고 항상 명시.

## 정확성 원칙

- 영상의 숫자는 코드에서 실제 계산한 값을 쓴다 (편미분 값, 공 경로, 근사 오차, 학습 곡선).
- 개념도(예: r 트레이드오프의 성능 곡선)는 화면에 "개념도"라고 표시한다.
- 논문 수치에는 출처를 단다.
